# 插件依赖关系

## 1. 一张图

```
                    ┌──────────────────────────────┐
                    │ astrbot_plugin_persona_growth │
                    │  写 diary.json / key_facts    │
                    │  写 surf_corpus / knowledge   │
                    └───────────┬──────────────────┘
                                │
          ┌─────────────────────┼─────────────────────┐
          ▼                     ▼                     ▼
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────────┐
│ self_memory      │  │ interest_profile │  │ topic_proficiency    │
│ 读 diary/facts   │  │ 读 diary         │  │ 读 corpus/knowledge  │
│ 写 memories      │  │ 写 prefs.json    │  │ 写 proficiency.json  │
└──────────────────┘  └────────┬─────────┘  └──────────┬───────────┘
                               │                       │
                               └──────────┬────────────┘
                                          ▼
                             ┌──────────────────────────────┐
                             │ group_proactive              │
                             │ 读 diary / prefs / proficiency│
                             │ 读知识库（可选）              │
                             │ 写 state / decisions / msgs   │
                             └──────────────────────────────┘

独立插件（不参与上面的数据流）：
  context_slim   —— 只改每次请求的上下文
  reply_pacing   —— 只控制发送间隔
  usage_cost     —— 只读 data_v4.db 的 provider_stats
  cross_group    —— 只走平台 API + aliases.json
  qq_profile     —— 只走 NapCat API
```

## 2. 数据文件依赖表

| 文件 | 写它的插件 | 读它的插件 | 没有时会怎样 |
|---|---|---|---|
| `persona_growth/diary.json` | `persona_growth` | `self_memory`、`interest_profile`、`group_proactive` | 相关功能跳过，不报错 |
| `persona_growth/key_facts.json` | `persona_growth`、`self_memory` | `self_memory` | 跳过事实召回 |
| `persona_growth/surf_corpus/` | `persona_growth` | `topic_proficiency` | 熟练度为空 |
| `persona_growth/knowledge.jsonl` | `persona_growth` | `topic_proficiency`、`persona_growth` 自己 | 知识卡为空 |
| `self_memory/memories.json` | `self_memory` | `self_memory` | 自动新建 |
| `interest_profile/prefs.json` | `interest_profile` | `group_proactive`、`topic_proficiency` | 群聊判定少一块偏好 |
| `topic_proficiency/proficiency.json` | `topic_proficiency` | `group_proactive`、`interest_profile` | 少一块熟练度 |
| `group_proactive/state.json` | `group_proactive` | 自己 | 自动新建，从头计数 |
| `group_proactive/decisions.jsonl` | `group_proactive` | 人（调参） | 不写也不影响发言 |
| `group_proactive/msgs/` | `group_proactive` | 自己 | 重启后少一点历史尾巴 |

> 所有「读」都是**容错**的：文件不存在、JSON 坏了、路径为空，插件会跳过对应功能，不会让主流程崩掉。所以不需要按严格顺序安装。

## 3. 最小可用组合

### 3.1 只想让聊天更稳、更省 token

```
context_slim
reply_pacing
```

不依赖任何数据文件，装上就能用。

### 3.2 只想要「会记事」

```
self_memory
```

可选加 `persona_growth`，让记忆能从日记里补充。

### 3.3 只想要「会成长」

```
persona_growth
```

它自己就能写日记、刷 B 站、抽事实。`self_memory` 不是必需，但装上之后「记住的事」才会在聊天里被主动召回。

### 3.4 想要完整的群聊养成

```
persona_growth
self_memory
interest_profile
topic_proficiency
group_proactive
reply_pacing
context_slim
```

`usage_cost`、`cross_group`、`qq_profile` 是管理员工具，按需加。

### 3.5 只要群聊主动，不要成长

```
group_proactive
```

可以跑，但：

- 没有 `diary.json` 时，它找话题的素材少。
- 没有 `prefs.json` / `proficiency.json` 时，判定层少两块参考。
- 建议至少把 `persona_diary_path`、`diary_file` 指向一个存在的日记文件；或者接受「更随机」的主动发言。

## 4. 启动顺序

不需要手动排序。所有插件都是独立加载的：

- `persona_growth` 的后台循环在 `on_astrbot_loaded` 后启动。
- `interest_profile` / `topic_proficiency` 各自轮询，文件没出现就等。
- `group_proactive` 启动会等平台反向 WebSocket 连上，再安排任务。
- `self_memory` 只在请求时读文件。

如果一定要看「谁先产出数据」：

```
persona_growth（先有 diary）
    → interest_profile / topic_proficiency（再加工）
        → group_proactive（最后消费）
```

但这是数据流顺序，不是安装/启动顺序。

## 5. 关掉某个插件会怎样

| 关掉 | 影响 |
|---|---|
| `persona_growth` | 不再有新日记/冲浪/知识卡；已有数据还在，其他插件仍能读旧数据 |
| `self_memory` | 不再自动召回长期记忆；`persona_growth` 仍会写 `key_facts.json`，但没人读 |
| `interest_profile` | `prefs.json` 不再更新；`group_proactive` 用旧数据或跳过 |
| `topic_proficiency` | `proficiency.json` 不再更新；知识库不再自动灌入 |
| `group_proactive` | 不再主动发言；被动回复仍由 AstrBot 正常处理 |
| `reply_pacing` | 回复可能连续快速发出 |
| `context_slim` | 历史里的图片/思考链/工具结果会一直带着，token 变高 |
| `usage_cost` | 只是查不了花费，不影响其他 |
| `cross_group` | 管理员不能跨群读/发 |
| `qq_profile` | 不能改签名/发说说 |

## 6. 多机器人 / 多平台

- 所有插件都按「当前 AstrBot 实例」工作，没有多租户隔离。
- `group_proactive.platform_id` 留空时自动取当前平台；如果你同时接了多个 aiocqhttp 账号，建议显式填平台 ID。
- `plugin_data/` 是按插件名分的，不按机器人账号分。一个 AstrBot 实例跑多个机器人时，它们会共享同一份日记/记忆/偏好。需要隔离就开多个 AstrBot 实例。

## 7. 升级时的数据兼容

- 插件代码升级不会动 `plugin_data/`。
- `config.json` 里新增的键如果不存在，代码会用 `DEFAULT_CONFIG` 兜底。
- 如果你用安装器的 `--force` 覆盖插件目录，`config.json` 会被模板覆盖（路径会重新生成），`plugin_data/` 不受影响。覆盖前先备份 `config.json`。

## 8. 和 AstrBot 本体的关系

这套插件只通过 AstrBot 的公开 API 工作：

- `star.Star`
- `filter.on_llm_request` / `on_decorating_result` / `on_agent_done` 等
- `context.get_using_provider_async` / `context.llm_generate`
- `context.kb_manager`
- `context.get_config()["admins_id"]`
- `astrbot.core.utils.astrbot_path`（算数据目录）
- `astrbot.core.agent.message.TextPart`（临时注入块）

**插件本身不修改 AstrBot 本体。** 但原作者的实例上有 9 个 AstrBot 本体补丁（表情、合并转发、引用、分段回复、定时任务管理员限制等），这些补丁现在单独放在 `core-patches/`，用 `tools/apply_core_patches.py` 应用，和插件互不依赖。

没有这些补丁时：

- QQ 表情可能只能按原文字符显示（本包已对 `parse_face_markers` 做 fallback，不会崩）。
- 「回旧消息带引用」可能不生效（取决于你的 `message_tools` 是否支持 `reply` 段）。
- 合并转发/文件正文/群历史里的表情解析可能不如原作者的完整。
- 主动任务的元信息可能写进会话历史（原作者的补丁才拦）。

这些都不影响插件加载和基本聊天。需要完整效果，见 `core-patches/使用说明.md`。
