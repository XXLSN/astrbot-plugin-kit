# 插件说明

> 路径里的 `<DATA>` 指 AstrBot 数据目录，`<PLUGIN_DATA>` 指 `<DATA>/plugin_data`。
> 所有插件都只声明支持 `aiocqhttp`，并且都带 `author: local`。
>
> **安装和配置直接交给 AI：** 把插件包和 `部署文档.md` 一起发给 AI 工具，让它代你装、代你改配置。本文只讲每个插件做什么、有哪些工具和命令。

---

## 1. `astrbot_plugin_persona_growth` — 人格成长

**做什么**

- 按聊天量自动写「人格日记」：今天和谁聊了什么、她自己的感受。
- 空闲时以游客身份刷 B 站、看文章，学说话方式、学梗/游戏/笑话/杂谈。
- 从聊天里抽取关于主人的长期事实（`key_facts.json`），给记忆插件用。
- 深读网页后整理成知识卡，写入 `knowledge.jsonl`，也可以灌进 AstrBot 知识库。
- 群聊里回得太密会「装累」，说一句累了后安静一段时间。
- 每次 LLM 请求把「此刻的脾气 + 最近日记 + 知识卡」挂在当前用户消息末尾（临时块，不落库），尽量不破坏前缀缓存。

**触发方式**

- 后台循环（`loop_interval_seconds`，默认 300 秒检查一次）。
- `on_llm_request` 注入成长状态。
- `on_waiting_llm_request` 处理「装累」。
- `on_decorating_result` 记录自己发出的文本。

**写入文件**

```
<PLUGIN_DATA>/astrbot_plugin_persona_growth/
├── diary.json          # 日记（核心数据）
├── meta.json           # 计数、上次写日记时间、已读素材等
├── turns.jsonl         # 聊天片段缓存
├── surf_history.log    # 冲浪记录（看了什么）
├── surf_corpus/        # 娱乐冲浪的原始素材
└── knowledge.jsonl     # 深读知识卡
```

**依赖**

- 一个聊天模型（`provider_id`，留空用默认）。
- 可选：AstrBot 知识库（`knowledge_kb_name`）。
- 网络：B 站公开页面。被反爬/断网时只影响冲浪，不影响聊天。

**能否单独用**：可以。它是整个成长体系的数据源头，建议先装它。

**注意**

- `diary_every_messages` 默认 24，`diary_min_hours` 默认 6，`diary_max_per_day` 默认 8。想快点看到效果就调小前两个、调大第三个。
- 日记是 AI 自己写的，可能夹带模型幻觉；它只是上下文素材，不是事实数据库。
- 冲浪内容会写入 `surf_corpus/`，占磁盘；`surf_max_per_day` 控制频率。

## 2. `astrbot_plugin_self_memory` — 自主记忆

**做什么**

- 机器人自己决定记什么、忘什么，不靠用户手动维护。
- 提供一组 LLM 工具（仅管理员）：
  - `memory_status`：看当前记忆条数/占用
  - `remember`：记一条
  - `recall`：按关键词回忆
  - `search_history`：搜历史聊天
  - `list_memories`：列出记忆
  - `forget_memory`：忘掉某条
  - `clear_chat_memory`：清空当前会话上下文
  - `clear_long_term_memory`：清空全部长期记忆（危险）
- 每次请求把常驻记忆拼进 system prompt；按关键词自动召回相关记忆和日记片段。

**触发方式**

- LLM 工具调用（管理员）。
- `on_llm_request` 注入常驻记忆和自动召回。

**写入文件**

```
<PLUGIN_DATA>/astrbot_plugin_self_memory/
├── memories.json      # 长期记忆（核心数据）
└── key_facts.json     # 关于主人的事实（persona_growth 也会写）
```

**依赖**

- 无强依赖；`diary_path` 指向 `persona_growth/diary.json` 时，会额外从日记里召回。

**注意**

- `clear_long_term_memory` 不可撤销；建议在 WebUI 里定期备份 `memories.json`。
- 常驻记忆越长，system prompt 越大，越费 token；用 `max_notes`、`pinned_char_budget` 控制。

## 3. `astrbot_plugin_interest_profile` — 兴趣偏好

**做什么**

- 只吃 `persona_growth` 写出的 `mode == "fun"` 的日记（娱乐冲浪），不碰学说话和聊天日记。
- 两道模型调用：整理员转录「她接触了什么」，再让机器人本人按人设打分。
- 分数本地按公式算（半衰期、滞后），写成 `prefs.json`，给群聊判定层用。

**触发方式**

- 后台轮询（`poll_interval_seconds`，默认 60 秒）。

**写入文件**

```
<PLUGIN_DATA>/astrbot_plugin_interest_profile/
├── prefs.json         # 兴趣偏好（核心数据）
├── events.jsonl       # 每次打分事件
├── score_log.jsonl    # 分数变化日志
└── state.json         # 已处理到哪一篇日记
```

**依赖**

- `persona_growth` 的 `diary.json`。
- 一个聊天模型（`provider_id`）。
- 可选：`topic_proficiency/proficiency.json`（用来做熟练度加权）。

**注意**

- `dry_run: true` 时只分析不落盘，适合先看效果。
- 分数会随时间衰减（`half_life_days`），不是永久标签。

## 4. `astrbot_plugin_topic_proficiency` — 话题熟练度

**做什么**

- 扫 `surf_corpus/` 和 `cards/` 里她真正看过的素材。
- 按「接触次数 × 深度 × 最近时间」算话题熟练度，写成 `proficiency.json`。
- 可在回答里注入「这个话题她熟不熟」。
- 可选把知识卡灌进 AstrBot 知识库（`kb_name`）。

**触发方式**

- 后台轮询（`poll_interval_seconds`，默认 300 秒）。

**写入文件**

```
<PLUGIN_DATA>/astrbot_plugin_topic_proficiency/
├── proficiency.json       # 熟练度（核心数据）
├── sources.jsonl          # 素材来源记录
├── knowledge_index.jsonl  # 已入库的知识卡 id
└── cards/                 # 知识卡
```

**依赖**

- `persona_growth` 的 `surf_corpus/`、`knowledge.jsonl`。
- 可选：`interest_profile/prefs.json`。
- 可选：AstrBot 知识库 + embedding 模型。

**注意**

- 没有素材时不会凭空算熟练度；新装时 `proficiency.json` 是空的，正常。
- 不配置 `kb_name` 时只算分，不入库。

## 5. `astrbot_plugin_group_proactive` — 群聊主动聊天

**做什么**

这是最大、最复杂的一个插件（约 350 KB）。核心行为：

- **上线补读**：启动后先读离线消息（最多 200 条；群看最近 6 小时，和主人私聊看 24 小时）。
- **群聊判该不该接**：本地规则 + 模型判定；@ / 引用 / 正文叫名字的优先。
- **被叫到但没 @**：用名字/昵称/QQ 号叫她会先读历史确认，再决定回不回。
- **回旧消息**：要回的那条隔了 8 条以上，会带引用。
- **话痨控制**：10 分钟最多 5 条；@ / 引用 / 手打 @ 名字不限。
- **静默**：她自己可以调 `mute_group_chat` 闭嘴；管理员可 `unmute_group_chat`。
- **私聊主动**：管理员热聊时补话；冷场后按 20/40/80/160 分钟退避；普通好友可选。
- **跨天账本**：记她最近反复说的话，避免复读。
- **消息图**：按群/天缓存消息，重启后恢复尾巴。

**工具 / 命令**

| 名称 | 权限 | 作用 |
|---|---|---|
| `trigger_group_proactive` | 管理员 | 手动触发一次群主动 |
| `trigger_private_proactive` | 管理员 | 手动触发一次私聊主动 |
| `mute_group_chat` | 机器人自己 | 在群里闭嘴 N 分钟 |
| `unmute_group_chat` | 管理员 | 解除闭嘴 |
| `/bot名称决策`（别名 `/决策统计`） | 管理员 | 看最近一天「回/不回」汇总 |

> 用 `--bot-name <名字>` 安装时，命令名也会跟着变成 `<名字>决策`（代码里的名字会被替换）。如果安装后手动改名，记得同步改 `main.py` 里的 `@filter.command(...)`。

**写入文件**

```
<PLUGIN_DATA>/astrbot_plugin_group_proactive/
├── state.json         # 群/私聊状态、计数器、上次说话时间
├── decisions.jsonl    # 每次「回/不回」的判断（调参必看）
├── ledger.json        # 跨天复读账本
└── msgs/              # 消息图缓存（按群/天）
```

**依赖**

- `persona_growth/diary.json`（找话题）。
- 可选：`interest_profile/prefs.json`、`topic_proficiency/proficiency.json`、知识库。
- 平台：`aiocqhttp`，需要能读群历史、发群消息。
- 模型：默认会话模型；判定层用 `get_using_provider_async`。

**注意**

- **默认 `dry_run: true`**，不真的发言。先观察 `decisions.jsonl`。
- `group_ids` 为空 = 不主动进群。
- `private_only_mode: true` = 只和主人私聊，群聊完全不碰。
- 判定层失败默认「不接」（`group_decision_fail_closed: true`），宁可少说。
- 这个插件依赖 AstrBot 的 `send_message_to_user` 工具；如果工具被禁用，它无法主动发言。

## 6. `astrbot_plugin_reply_pacing` — 回复节奏

**做什么**

- 同一个人连着问好几件事时，把回复按会话限速，几条消息之间留几秒，避免一口气刷屏。
- 管理员可豁免。

**触发方式**

- `on_decorating_result`，在发送前等待。

**配置**

- `private_gap_seconds`（默认 4）
- `group_gap_seconds`（默认 3）
- `jitter_seconds`（默认 1.5）
- `max_wait_seconds`（默认 30）
- `admin_exempt`（默认 true）

**写入文件**：无。

## 7. `astrbot_plugin_context_slim` — 上下文瘦身

**做什么**

发送前清理历史里的：

- 旧图片（只留最近 `keep_recent_images` 张）
- 历史思考链（`clear_historical_think`）
- 超长工具结果（截到 `tool_result_max_chars`）
- 重复的时间提醒（`compact_historical_reminders`）
- 旧群聊快照（只留最近 N 个）

**触发方式**

- `on_llm_request`，直接改请求里的 context。

**配置**

- `enabled`、`diagnose`、`verbose`
- `keep_recent_images`（默认 1）
- `keep_recent_tool_results`（默认 5）
- `tool_result_max_chars`（默认 100）
- `trim_quantum` / `block_trim_quantum`：按几条一组裁，避免破坏消息配对

**写入文件**：无。

**注意**

- 它改的是「发给模型的历史」，不改数据库。
- 如果发现模型突然「忘了前面说过的话」，先把 `keep_recent_images`、`keep_recent_tool_results` 调大，或临时 `enabled: false` 对比。

## 8. `astrbot_plugin_usage_cost` — 用量花费统计

**做什么**

- 从 AstrBot 的 `provider_stats` 表按天汇总 token。
- 按配置的单价估算花费，区分高峰/空闲、缓存命中。
- LLM 工具 `query_usage_cost`（仅管理员）。

**依赖**

- `<DATA>/data_v4.db` 里的 `provider_stats` 表。
- 单价在 `config.json` 的 `prices` / `fallback` 里改。

**注意**

- AstrBot 本身不记金额，只记 token；金额是估算。
- 如果 `provider_stats` 没记录某类请求，统计会偏低。

## 9. `astrbot_plugin_cross_group` — 跨群助手

**做什么**

管理员在私聊里通过 LLM 工具操作群：

| 工具 | 作用 |
|---|---|
| `list_groups` | 列出机器人所在的群 |
| `read_group_history` | 读指定群最近历史 |
| `send_group_message` | 往指定群发消息 |
| `set_group_alias` | 给群设别名，方便用名字指代 |

**写入文件**

```
<DATA>/plugins/astrbot_plugin_cross_group/aliases.json
```

> 别名存在插件目录里，升级覆盖插件目录会丢；介意的话手动备份。

**依赖**

- 管理员 `admins_id`。
- `aiocqhttp` 平台，且适配器支持群列表/群历史 API。

## 10. `astrbot_plugin_qq_profile` — QQ 资料与空间

**做什么**

管理员通过 LLM 工具：

| 工具 | 作用 |
|---|---|
| `set_qq_profile` | 改机器人昵称/签名 |
| `publish_qzone_moment` | 发 QQ 空间说说 |
| `delete_qzone_moment` | 删说说 |

**依赖**

- NapCat 已登录，且账号有对应权限。
- 管理员 `admins_id`。
- 平台 `aiocqhttp`。

**注意**

- 发说说/改资料是**对外可见**的操作，建议在提示词或使用习惯上要求二次确认。
- 不同 NapCat 版本 API 可能有差异；失败先看日志里的 HTTP 返回。
