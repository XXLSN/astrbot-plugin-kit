# 配置说明

> **改配置之前：** 把插件包和 `部署文档.md` 一起发给 AI 工具，让它对照本文改 `config.json`——自己手改容易漏字段或写错类型，装完跑不起来。

## 0. 先搞懂配置放在哪

每个插件目录下有一个 `config.json`：

```
<DATA>/plugins/astrbot_plugin_xxx/config.json
```

这些插件是**直接读这个 JSON 文件**的，不走 AstrBot 的 `_conf_schema.json`。所以：

- WebUI 的插件配置页可能显示不出这些项，或者显示不全。
- 改配置 = 用文本编辑器改 `config.json` → 保存 → 在 WebUI 重载插件（或重启）。
- 安装器会按你的 AstrBot 数据目录把路径写进去；路径不要手写死，除非你知道自己在做什么。

> 改之前先备份整个 `plugins/` 目录。JSON 不能有注释、不能有多余逗号。

## 1. `astrbot_plugin_group_proactive`

这是最需要调的插件。默认保守：不主动进群、dry-run。

### 1.1 基础

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `dry_run` | `true`（安装器生成） | `true` 只判断不发言；确认后再改 `false` |
| `platform_id` | `""` | 留空自动取当前平台；多平台时填平台 ID |

## 10. 改配置后的检查

1. JSON 能不能解析：

   ```bash
   python -c "import json;json.load(open(r'<路径>/config.json',encoding='utf-8'));print('ok')"
   ```

2. 路径是否存在（目录可以不存在，插件会自己建；文件不存在也正常，会新建）。
3. 重载插件，看日志有没有 `config.json` 解析失败。
4. 改 `group_proactive` 后先看 `decisions.jsonl`，不要直接开 `dry_run: false`。
