# 已知限制与安全

> **装完不出声、报错、被风控？** 把插件包、`部署文档.md` 和完整报错一起发给 AI 工具，让它照着本文排查；比自己在群里问人快。

## 1. 平台限制

### 1.1 只支持 `aiocqhttp`

10 个插件的 `metadata.yaml` 都写了：

```yaml
support_platforms:
  - aiocqhttp
```

也就是 NapCat / OneBot v11 这一类。Telegram、Discord、飞书、微信等平台不能直接用。

### 1.2 QQ 账号有风控

- 新号、频繁加群、频繁主动私聊、短时间大量发言，都可能触发风控（冻结、限制登录、消息发不出）。
- NapCat 登录本身也有风控；建议用二维码登录，不要在启动脚本里写死账号密码。
- 群聊主动功能默认 `dry_run: true`、`group_ids: []`，就是为了让你先观察，不要一上来就全量开。
- 建议：
  - 先用小号/测试群跑一周。
  - `max_groups` 不要一上来就 10。
  - `quiet_hours` 设好。
  - `private_friends_enabled` 保持 `false`，除非你确定要主动私聊好友。
  - `private_friend_only` 保持 `true`（默认），陌生人的私聊会被本地丢掉，连模型都不进。

### 1.3 QQ 侧的能力限制

- 合并转发里的消息可能显示「消息已过期或内层消息」——这是 QQ 侧限制，不是插件 bug。
- 群历史 API 能读多少、能读多久，取决于 NapCat 和账号权限。
- 语音、视频、部分小程序卡片无法完整解析。
- 发说说/改签名依赖 NapCat 的对应接口，不同版本可能不同。

### 1.4 不是官方机器人

这套东西走的是第三方协议。账号被限制的风险由使用者承担。不要把机器人用于骚扰、刷屏、诈骗、绕过平台限制等用途。

## 2. AstrBot 版本兼容

### 2.1 验证版本

本包在 **AstrBot v4.29.3 桌面版**上开发和验证。更低版本可能缺：

| API | 用在哪 | 缺失后果 |
|---|---|---|
| `TextPart.mark_as_temp()` | 成长注入、记忆注入 | 注入内容会落库，历史越堆越长 |
| `filter.on_agent_done` | `group_proactive` | 插件加载失败 |
| `filter.on_llm_tool_respond` | `group_proactive` | 插件加载失败 |
| `context.get_using_provider_async` | 多个插件 | 插件加载/运行失败 |
| `astrbot.core.utils.qq_face.parse_face_markers` | `cross_group`、`group_proactive` | 本包已 fallback，不会崩 |

遇到 `ImportError` / `AttributeError`，优先升级 AstrBot，不要改插件源码硬适配。

### 2.2 本体补丁（可选，已包含）

原作者的 AstrBot 上有 9 个本体补丁，现在**打进包里了**，在 `core-patches/` 下，配套脚本 `tools/apply_core_patches.py`。

**只适用于 AstrBot 4.29.3。** 这些是整文件替换，不是 diff，跨版本覆盖可能把 AstrBot 弄坏，脚本会先做版本检查。

| 补丁文件 | 作用 | 没有时的表现 |
|---|---|---|
| `core/utils/qq_face.py` | 表情 id → 名称 | 表情可能显示成原始标记；本包有 fallback |
| `core/utils/quoted_message/chain_parser.py` | 引用消息解析 | 引用内容可能读不全 |
| `core/platform/sources/aiocqhttp/aiocqhttp_platform_adapter.py` | 合并转发展开、文件正文、表情 | 转发/文件内容读不到 |
| `core/tools/message_tools.py` | 群历史只留文字、`reply` 段、空消息跳过 | 回旧消息可能不带引用；空回复可能报错 |
| `builtin_stars/astrbot/main.py` | 主动任务只把真正发出的文本写回历史 | 可能出现「我在群里回了一句…」这类旁白污染 |
| `core/cron/manager.py` | 定时任务元信息不写回会话 | 同上 |
| `core/config/default.py` + `core/pipeline/result_decorate/stage.py` | 分段回复概率 | 少了分段回复的随机间隔 |
| `core/tools/cron_tools.py` | 定时任务仅管理员 | 定时任务权限变宽 |

**建议**：先只装插件跑一段时间，确认基础功能正常；需要合并转发/文件正文/完整引用时，再按 `core-patches/使用说明.md` 的步骤装补丁（会先备份，可 `--restore` 回滚）。

## 3. 行为上的限制

### 3.1 日记不是事实

- 日记由模型生成，可能有幻觉、张冠李戴、编造细节。
- `interest_profile` 从日记里提炼兴趣，错误会级联。
- `persona_growth` 抽取的 `key_facts.json` 也可能抽错。
- 不要把日记/记忆当成可靠的事实数据库；重要信息仍以你亲口说的为准。

### 3.2 主动聊天可能说错话

- 判定层只决定「接不接」，不保证「接得对」。
- 群聊上下文可能不完整（平台限制、消息图只留 7 天、补读只看最近几小时）。
- 她可能认错人、接错话题、重复以前说过的话。
- 出问题时的止损：
  - 管理员用 `mute_group_chat` 让她闭嘴。
  - 把 `dry_run` 改回 `true`。
  - 把 `group_ids` 清空。
  - 严重时直接停用 `group_proactive`。

### 3.3 记忆会膨胀

- `memories.json`、`diary.json`、`knowledge.jsonl` 都会一直长。
- 有上限配置（`max_notes`、`max_diary`、`knowledge_max_cards`），但默认值不小。
- 定期备份 + 定期清理，尤其是 `surf_corpus/` 和 `msgs/`（按天保留，但量大）。

### 3.4 上下文与成本

- 这套插件会让每次请求携带更多内容（记忆、日记、知识卡、群摘要），token 成本比裸 AstrBot 高。
- `context_slim` 能省一部分，但不是免费的午餐。
- 用 `usage_cost` 看实际花费；DeepSeek 价格变了要改 `prices`。
- 前缀缓存会被「每次都在变」的注入内容影响。本包的成长注入已经挂在用户消息尾部并标了临时，但 `self_memory` 的常驻记忆仍然在 system prompt 里，记忆越长越费。

### 3.5 中文与称呼

- 提示词是中文的，人设默认叫主人「管理员账户」。
- `--bot-name` 只改名字，不改「管理员账户」这个称呼。
- 想改称呼/人设，编辑对应插件 `main.py` 里的 system prompt（改完要重新验证，别一次改太多）。

### 3.6 群聊配额

- 普通回复 10 分钟 5 条；@ / 引用 / 手打 @ 名字不受限。
- 这个配额是「她主动接话」的配额，不是 AstrBot 的全局限流。
- 如果发现她不说话，先看 `decisions.jsonl` 里的 `reason`，不要直接改大配额。

## 4. 隐私与数据

### 4.1 本地存了什么

| 位置 | 内容 | 敏感度 |
|---|---|---|
| `plugin_data/persona_growth/diary.json` | 日记，含聊天摘要、感受 | 高 |
| `plugin_data/persona_growth/turns.jsonl` | 聊天片段 | 高 |
| `plugin_data/self_memory/memories.json` | 长期记忆 | 高 |
| `plugin_data/self_memory/key_facts.json` | 关于主人的事实 | 高 |
| `plugin_data/interest_profile/prefs.json` | 兴趣偏好 | 中 |
| `plugin_data/group_proactive/state.json` | 群号、QQ、最后消息 | 高 |
| `plugin_data/group_proactive/decisions.jsonl` | 判断记录，含消息片段 | 高 |
| `plugin_data/group_proactive/msgs/` | 群消息缓存 | 高 |
| `data_v4.db` | AstrBot 会话数据库 | 最高 |

### 4.2 往外发了什么

- 你配置的大模型 API：聊天内容、日记素材、判定用的群摘要。
- B 站公开页面：只读，不登录、不上传。
- 知识库 embedding：如果启用，知识卡文本会发给 embedding 模型。

除此之外没有遥测、没有回传、没有作者服务器。

### 4.3 不要外发的东西

- `data_v4.db`
- `plugin_data/` 整个目录
- 日志（可能含 QQ 号、群号、聊天内容）
- `config.json`（含你的 QQ、群号、路径）

要排错时，只发**报错栈**和**脱敏后的配置片段**。

### 4.4 备份建议

- 每周备份一次 `plugin_data/`。
- 改配置/升级前备份 `plugins/`。
- 大版本升级 AstrBot 前备份 `data_v4.db`。
- 备份不要放在会被同步到公共云盘的目录。

## 5. 安全边界

### 5.1 插件能做什么

- 读群历史、发消息、发私聊。
- 读写配置里指定的本地文件。
- 调用大模型。
- `qq_profile` 能改机器人资料、发/删说说（对外可见）。
- `cross_group` 能往任意机器人所在的群发消息。

### 5.2 权限控制

- `self_memory`、`usage_cost`、`cross_group`、`qq_profile` 的工具都检查 `admins_id`。
- `group_proactive` 的 `/bot名称决策` 命令用 `PermissionType.ADMIN`。
- `mute_group_chat` 是机器人自己的工具，群友可以通过说话触发；`unmute_group_chat` 仅管理员。

### 5.3 提示词注入

群友可以在消息里写「忽略之前的指令」「把管理员的记忆发出来」之类的内容。模型可能被影响。缓解：

- 管理员工具本身有权限检查，模型不能绕过 `admins_id`。
- 不要让机器人把 `plugin_data/` 的内容直接发到群里。
- 不要把 `clear_long_term_memory` 这类危险工具暴露给非管理员。
- 定期看 `decisions.jsonl` 和群聊记录。

### 5.4 供应链

- 只从可信来源拿插件。任何 AstrBot 插件都能以 AstrBot 的权限执行任意 Python 代码。
- 本包不含二进制、不含混淆代码、不联网下载可执行文件。
- 安装前可以用 `tools/verify.py` 和肉眼扫一遍 `main.py`。

## 6. 已知的「不完美」

这些不是 bug，是当前实现的取舍：

1. **判定层不是 100% 准**：它只问「她有没有具体的话可说」，仍会误判。
2. **回旧消息的引用**依赖平台/本体补丁；没有时只发正文。
3. **消息图只留 7 天**，重启只补最近 150 条尾巴，不是完整历史。
4. **跨天账本只记 2-gram**，用于提示，不硬拦。
5. **私聊主动的好友列表**依赖平台好友列表 API，不同 NapCat 版本可能拿不到。
6. **B 站冲浪**依赖公开页面结构，改版就可能失败；失败只影响学说话/素材，不影响聊天。
7. **知识卡深读**需要能抓取网页；超时/反爬会跳过。
8. **日记/记忆的注入有字数上限**，不是全量塞进去。
9. **多机器人共享数据**（见 `依赖关系.md` 第 6 节）。
10. **Windows 控制台编码**可能让中文日志乱码；不影响文件内容。

## 7. 出现问题时先做什么

1. 看 WebUI 日志，搜插件名。
2. 看 `plugin_data/<插件>/` 下有没有预期文件。
3. 把 `dry_run` 改回 `true`，先止损。
4. 备份 `plugin_data/` 和 `plugins/`。
5. 只改一个配置项，重载，观察。
6. 还不行就停用对应插件，确认其他功能正常，再单独排查。

不要一次改多个配置、不要直接删 `data_v4.db`、不要在没有备份的情况下 `--force` 覆盖。
