# AstrBot 本体补丁 · 使用说明

> 这里放的是对 **AstrBot 本体**（`backend/app/astrbot/...`）的修改，不是插件。
> 插件包本身不装这些也能跑；装了之后，合并转发、文件正文、QQ 表情、引用回复、主动任务历史等行为才完整。
>
> **适用版本：AstrBot 4.29.3。** 其他版本不要直接覆盖，见第 6 节。
>
> 本说明有两个出处：完整插件包里的 `core-patches/使用说明.md`，以及单独的「本体补丁包」。两个包里的相对路径一致（`core-patches/...`、`tools/apply_core_patches.py`），以下命令都在包根目录执行。

---

## 1. 文件清单（9 个）

| # | 文件（相对 `backend/app/astrbot/`） | 改了什么 | 影响哪些插件/行为 |
|---|---|---|---|
| 1 | `builtin_stars/astrbot/main.py` | 主动任务只把真正发进群的文本写回群历史；一句没发就整条不记 | `group_proactive` 主动消息、历史干净度 |
| 2 | `core/config/default.py` | 新增「分段回复概率」配置项 | 分段回复 |
| 3 | `core/cron/manager.py` | 主动聊天任务不把定时任务元信息写回会话 | `group_proactive`、上下文不被污染 |
| 4 | `core/pipeline/result_decorate/stage.py` | 按概率把一条回复拆成多段发送 | 分段回复、回复节奏 |
| 5 | `core/platform/sources/aiocqhttp/aiocqhttp_platform_adapter.py` | 合并转发展开（含图片/文件，带上限）；直接发来的文件抽取正文；QQ 表情/超级表情转可读文本 | 读转发、读文件、表情 |
| 6 | `core/tools/cron_tools.py` | 定时任务只允许 `admins_id` 里的管理员操作 | 定时任务权限 |
| 7 | `core/tools/message_tools.py` | 群历史只留文字；表情转小黄脸；UTC 转本地时间；`send_message_to_user` 支持 `reply` 段；空白消息跳过 | 群聊历史、回旧消息引用、沉默不报错 |
| 8 | `core/utils/quoted_message/chain_parser.py` | 引用消息解析（无 `# [本地修改]` 标记） | 引用链、回复上下文 |
| 9 | `core/utils/qq_face.py` | 表情 id → 名称映射（无 `# [本地修改]` 标记） | QQ 表情显示成名字 |

前 7 个文件里带 `# [本地修改]` 注释，搜索这个关键词就能定位改动点；第 8、9 个没有标记，是靠修改时间判断的。

`manifest.json` 里记录了每个文件的 SHA256 和来源版本。脚本用它判断「目标是不是已经是补丁版本」。

> 备注：本地备份清单里还有一个 `builtin_stars/astrbot/group_chat_context.py`（群上下文图片占位统一成「[图片]」），属于作者自己后来的单点改动，**不在对外发布的 9 个补丁里**。

## 2. 先决条件

1. **AstrBot 版本必须是 4.29.3**（或与 manifest 完全一致）。
2. 已经能正常启动 AstrBot，插件也装好了。
3. **停掉 AstrBot**。Windows 桌面版从托盘退出，确认任务管理器里没有 `AstrBot` / `python` 后端进程。
4. 知道 AstrBot 安装目录（不是数据目录）：
   - 桌面版默认：`%LOCALAPPDATA%\AstrBot`，例如 `C:\Users\<你>\AppData\Local\AstrBot`
   - 自定义安装：你当初安装时选的目录
   - 判断标准：目录下有 `backend\app\astrbot\` 和 `backend\python\`
5. 先备份整个 `backend\app\`（脚本也会单独备份要改的文件，但整个目录更稳）。

PowerShell 备份示例：

```powershell
$home = "$env:LOCALAPPDATA\AstrBot"
$backup = "$env:USERPROFILE\Desktop\astrbot-app-backup-$(Get-Date -Format yyyyMMdd-HHmmss)"
Copy-Item "$home\backend\app" "$backup" -Recurse
Write-Host "备份到 $backup"
```

## 3. 推荐方式：用脚本

### 3.1 先预览

```bash
python tools/apply_core_patches.py --astrbot-home "<AstrBot安装目录>" --dry-run
```

期望：

- 打印当前版本和补丁版本。
- 列出 9 个文件，标 `[预览]` 或 `[已是补丁]`。
- 不写任何文件。

如果版本不一致，脚本会拒绝；看到 `[拒绝] 版本不一致` 就停下来，不要加 `--force`。

### 3.2 正式应用

确认 AstrBot 已停止，然后：

```bash
python tools/apply_core_patches.py --astrbot-home "<AstrBot安装目录>"
```

脚本会：

1. 再检查一次版本。
2. 把原文件备份到 `<AstrBot安装目录>\core-patch-backup-<时间戳>\`，目录结构和 `backend/app/...` 一致。
3. 复制 9 个补丁文件。
4. 用 AstrBot 自带的 Python（`backend/python/python.exe`）做语法检查。
5. 打印备份目录。

记下备份目录，回滚要用。

### 3.3 重启并验收

重启 AstrBot，按第 5 节逐项检查。

### 3.4 回滚

```bash
python tools/apply_core_patches.py --astrbot-home "<AstrBot安装目录>" --restore "<脚本打印的备份目录>"
```

然后重启。

> `--restore` 只恢复 manifest 里的 9 个文件。如果你还改过别的本体文件，用第 2 节的整目录备份恢复。

---

## 4. 手动方式

不想跑脚本就手动复制：

1. 停 AstrBot。
2. 把 `core-patches/backend/app/astrbot/...` 下的每个文件，按同样的相对路径覆盖到 `<AstrBot安装目录>/backend/app/astrbot/...`。
3. 覆盖前把目标文件备份到别处。
4. 重启。

手动方式没有版本检查、没有 SHA 校验、没有自动备份，**不如脚本稳**，只建议在你清楚每个文件作用时用。

## 5. 验收清单

重启后逐项试：

| 行为 | 怎么试 | 通过标准 |
|---|---|---|
| 合并转发可见 | 群里转发一条带文字/图片/文件的聊天记录，然后 @ 机器人问「上面转了啥」 | 它能说出转发里的内容，不是「消息已过期」 |
| 文件正文 | 直接发一个 txt/PDF/Word/Excel 给机器人 | 它能读到文件里的文字 |
| QQ 表情 | 发几个 QQ 小黄脸，再问它看到了什么 | 表情显示成名字/可读文本，不是空白 |
| 群历史 | 在群里聊几句，再 @ 它问刚才聊了什么 | 历史里没有 `[图片]` 占位符堆叠，时间是对的 |
| 引用回复 | 引用一条 10 条以前的消息问它 | 它的回复带引用气泡（取决于平台/账号权限） |
| 沉默不报错 | 让它「这次别回」 | 日志里是 `skipped`，不是发送失败重试 |
| 定时任务权限 | 用非管理员 QQ 试着操作定时任务 | 被拒绝 |
| 分段回复 | 正常聊天，观察长回复 | 偶尔分成 2–3 条，不是每次一整段 |
| 主动任务历史 | 触发一次主动发言，看会话记录 | 没有「我在群里回了一句…」这类旁白；没发出去时不写记录 |

不是每一项都必须通过：引用气泡、文件解析受 NapCat 版本和账号权限影响。

## 6. 版本不一致怎么办

**不要直接覆盖。** 这些是「整文件替换」，不是 diff 补丁。AstrBot 升级后，官方可能已经改了同一个文件；用 4.29.3 的文件覆盖新版本，轻则功能异常，重则启动失败。

处理顺序：

1. 先看新版本有没有官方支持这些行为（比如官方自己加了合并转发解析）。
2. 有官方支持 → 不装补丁。
3. 没有 → 找原作者要**对应版本**的补丁文件。
4. 实在要试：
   - 备份整个 `backend/app`；
   - 加 `--force` 只跳过版本检查，不跳过备份；
   - 启动后第一时间看日志，有报错立刻 `--restore`。

脚本的 `--force` 只是「允许跨版本尝试」，不是「保证能跑」。

---

## 7. AstrBot 升级后

桌面版升级会把 `backend/` 整个重新铺一遍，**补丁会被官方文件覆盖**。升级后：

1. 先正常启动一次，确认新版本能用。
2. 看新版本是否还需要这些补丁。
3. 需要的话，用对应版本的补丁重新应用。
4. 重新跑第 5 节验收。

不要升级完直接把旧补丁盖回去——版本可能已经变了。

---

## 8. 风险与安全

- 这些文件以 AstrBot 后端权限运行，能读消息、发消息、读写文件。只从可信来源获取。
- 补丁会让 AstrBot 脱离官方更新路径；出问题不能指望官方支持。
- 补丁里没有账号密码、API Key、QQ 号；`manifest.json` 只有文件哈希。
- 原作者的人设称呼已从注释里去掉，但代码逻辑保留。
- 应用前建议用编辑器打开几个文件，搜索 `# [本地修改]` 看一眼改动。

---

## 9. 和插件的关系

不装补丁时：

- 10 个插件都能加载、能聊天。
- `parse_face_markers` 有 fallback，不会因为缺 `qq_face` 崩溃。
- 但合并转发、文件正文、表情、引用回复、主动任务历史这些会退化。

装了补丁后：

- `group_proactive` 的「回旧消息带引用」才完整。
- 群历史/上下文更干净，token 更省。
- 主动任务不会把旁白写进会话。
- 表情和文件能被模型看到。

建议顺序：**先装插件、跑通；再装本体补丁、逐项验收。** 不要两个一起上，出问题不好定位。
